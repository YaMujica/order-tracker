### 1. Root Cause Analysis

Telemetry evidence in [evidence.json](file:///home/yami/Documents/ai-dev-tools-zoomcamp-homeworks/hw-4/incident-response/incidents/incident-20261004-081159/evidence.json) (Prometheus 5xx count and Loki access logs) demonstrated that HTTP 500 errors were triggered during `GET /api/orders/{order_id}` requests for express orders such as `express-1002`.

Investigation of [`order_detail`](file:///home/yami/Documents/ai-dev-tools-zoomcamp-homeworks/hw-4/app/main.py#L54-L60) in [app/main.py](file:///home/yami/Documents/ai-dev-tools-zoomcamp-homeworks/hw-4/app/main.py) identified the defect:

```python
def order_detail(row):
    order = as_dict(row)
    if order["priority"] == "express":
        placed_at = datetime.fromisoformat(order["created_at"])
        estimated_at = placed_at.replace(day=placed_at.day + 2)
        order["estimated_delivery"] = estimated_at.date().isoformat()
    return order
```

- For orders placed near the end of a month (such as `express-1002`, seeded at the previous month's end), `placed_at.day + 2` exceeded the valid number of days in that month.
- Attempting `placed_at.replace(day=placed_at.day + 2)` raised an unhandled `ValueError: day is out of range for month`, causing the endpoint to fail with an HTTP 500 Internal Server Error.

---

### 2. Remediation & Code Changes

1. **Date Arithmetic Fix in [`app/main.py`](file:///home/yami/Documents/ai-dev-tools-zoomcamp-homeworks/hw-4/app/main.py#L54-L60)**:
   Updated [`order_detail`](file:///home/yami/Documents/ai-dev-tools-zoomcamp-homeworks/hw-4/app/main.py#L54-L60) to use standard date offsets via `timedelta(days=2)` instead of directly modifying the day component:
   ```python
   def order_detail(row):
       order = as_dict(row)
       if order["priority"] == "express":
           placed_at = datetime.fromisoformat(order["created_at"])
           estimated_at = placed_at + timedelta(days=2)
           order["estimated_delivery"] = estimated_at.date().isoformat()
       return order
   ```

2. **Automated Test Coverage in [`tests/test_api.py`](file:///home/yami/Documents/ai-dev-tools-zoomcamp-homeworks/hw-4/tests/test_api.py#L38-L45)**:
   Added [`test_express_order_detail`](file:///home/yami/Documents/ai-dev-tools-zoomcamp-homeworks/hw-4/tests/test_api.py#L38-L45) to ensure seeded month-end express orders correctly compute `estimated_delivery` and return HTTP 200:
   ```python
   def test_express_order_detail(client):
       response = client.get("/api/orders/express-1002")
       assert response.status_code == 200
       data = response.json()
       assert data["id"] == "express-1002"
       assert data["priority"] == "express"
       assert "estimated_delivery" in data
   ```

### 4. Final Diagnosis & Concluding Response

The root cause was improper month rollover arithmetic using `.replace(day=placed_at.day + 2)` in [`order_detail`](file:///home/yami/Documents/ai-dev-tools-zoomcamp-homeworks/hw-4/app/main.py#L54-L60). The fix using `+ timedelta(days=2)` resolves the `ValueError`, verified both by the test suite passing and live endpoint validation returning HTTP 200 OK. The incident is resolved and the service is fully operational.
